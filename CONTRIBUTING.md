# Contributing to Open Healthcare Agentic Platform

Thank you for your interest in contributing to the **Open Healthcare Agentic Platform**! We are committed to fostering a vendor-neutral, evidence-grounded, and open-source community for healthcare artificial intelligence and cloud-native engineering.

---

## 1. Development Principles

1. **Evidence Grounding First**: Never compromise on verifiable clinical evidence. Every medical, provider, or clinical claim generated by the system must be anchored to authoritative public data (NPPES, PubMed, CMS, MedlinePlus).
2. **Deterministic Validation**: Always prioritize deterministic validation over statistical guesswork. Guardrails, NPI validations, and domain checks must execute predictably.
3. **Vendor Neutrality**: Do not introduce dependencies on closed-source or proprietary cloud APIs. All local capabilities must run without subscription keys.
4. **Cloud-Native Standards**: Follow CNCF conventions for OpenTelemetry instrumentation, container hardening (non-root users), and Kubernetes/Helm deployments.

---

## 2. Local Development Setup

### Prerequisites
- Python 3.12+
- `uv` (recommended) or standard `pip`
- Docker & Docker Compose (for container workflows)
- Ollama (optional, for real local Gemma 4 inference)

### Setup Steps
```bash
# 1. Clone repository
git clone https://github.com/hastimal/open-healthcare-agentic-platform.git
cd open-healthcare-agentic-platform

# 2. Create virtual environment
python3.12 -m venv .venv
source .venv/bin/activate

# 3. Install in editable mode with development dependencies
pip install --upgrade pip
pip install -e ".[dev]"

# 4. Copy environment configuration
cp .env.example .env
```

## 3. Quality Gates & Testing

Before launching containers, run `uv run python scripts/run_demo.py --check-only`.
See the [developer troubleshooting guide](docs/developer-guide.md) for macOS,
Ubuntu/Debian and Windows WSL2 setup, port conflicts, Ollama and read-only status
checks. Existing `--no-browser` usage remains supported.

All contributions must pass strict local quality checks before opening a pull request:

```bash
# 1. Ruff Linting & Formatting Check
uv run ruff check .
uv run ruff format --check .

# 2. Strict Static Type Checking
uv run mypy src tests

# 3. Offline Pytest Suite (must maintain >= 90% coverage)
uv run pytest -m "not live" --cov=healthcare_agents --cov-report=term-missing

# 4. Helm Linting (if modifying charts)
helm lint charts/open-healthcare
```

---

## 4. Pull Request Guidelines

1. **Branching**: Always branch off the latest `main` branch. Use descriptive names like `feat/add-feature-name` or `fix/issue-description`.
2. **Atomic Commits**: Keep commits focused and logically organized with conventional commit messages (`feat: ...`, `fix: ...`, `docs: ...`, `test: ...`).
3. **Documentation**: Update documentation in `docs/` and `README.md` if your change modifies CLI flags, configuration parameters, or architectural behavior.
4. **CI Green**: Verify that all GitHub Actions workflows pass cleanly on your pull request.
